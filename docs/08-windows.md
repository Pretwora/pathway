# Pathway — работа на Windows

Инструкция для запуска проекта на новом Windows-компьютере, где ничего не настроено.

## Главное ограничение: на Windows нет iOS

iOS-симулятор существует только на macOS — это ограничение Apple, обойти нельзя.
Собрать iOS-версию на Windows тоже невозможно (нужен Xcode). iOS-сборку и её
проверку продолжаем на Mac.

Живое превью на Windows даёт **эмулятор Android** из Android Studio: выбор модели
телефона, тап пальцем, мгновенное обновление при правке кода — всё то же самое,
только Android, а не iOS. Логика, экраны и данные у приложения общие, так что
проверка на Android честно показывает почти всё.

## Что теряется без Mac

- сборка и превью под iOS;
- релизный `.ipa` для App Store.

Всё остальное — код, логика, экраны, Android-сборка, тесты, публикация в Google
Play — на Windows доступно полностью.

## 1. Поставить один раз

**Claude Code, Git for Windows и Node.js LTS ставит человек** — без них Клод не
сможет ни клонировать репозиторий, ни поставить зависимости.

| Что | Откуда | Зачем |
|---|---|---|
| **Claude Code** | как ставился на Mac | вся работа идёт через него — ставится **первым** |
| **Git for Windows** | git-scm.com | клонировать репозиторий |
| **Node.js LTS** | nodejs.org | движок проекта |
| **JDK 17** (Temurin) | adoptium.net | сборка Android |
| **Android Studio** | developer.android.com/studio | Android SDK + эмулятор + выбор моделей телефонов |

Последние два вручную качать не обязательно: на Windows 11 есть `winget`, и Клод
ставит их сам.

```bash
winget install --id EclipseAdoptium.Temurin.17.JDK -e
winget install --id Google.AndroidStudio -e
```

**Мастер первого запуска Android Studio прокликивает человек** — это GUI, обойти
нечем. Отказаться от импорта настроек → тип установки **Standard** → принять
лицензии → **Finish**. Скачается ~2–3 ГБ.

Дальше переменные среды пропишет Клод:

- `JAVA_HOME` → папка JDK 17;
- `ANDROID_HOME` → `%LOCALAPPDATA%\Android\Sdk`;
- в `Path` добавить `%ANDROID_HOME%\platform-tools`, `%ANDROID_HOME%\emulator` и
  `%ANDROID_HOME%\cmdline-tools\latest\bin`.

### Чего мастер Standard не ставит

Двух вещей в стандартной установке нет, и без них дальше не поехать:

- **`cmdline-tools`** — это `sdkmanager` и `avdmanager`, без них эмулятор из
  командной строки не создать;
- **системный образ Android** — каталог `system-images` пустой, эмулятору нечего
  запускать (сам `emulator.exe` при этом на месте, что путает).

Клод доставит оба. `cmdline-tools` — распаковкой архива с `dl.google.com` прямо в
`%ANDROID_HOME%\cmdline-tools\latest`; **распаковывать через глубокий временный
каталог нельзя** — упирается в лимит длины пути Windows в 260 символов и рушится
на середине. Образ — через `sdkmanager`, брать под ту же версию платформы, что
поставил мастер.

Лицензию `android-sdk-license` мастер Studio принимает сам, и её достаточно для
образов `google_apis`. Отдельно вызывать `sdkmanager --licenses` не нужно — и не
выйдет: из конвейера PowerShell он ввод не читает и молча отвечает «нет».

## 2. Забрать проект

Репозиторий приватный, а Клод в неинтерактивной сессии не может ответить на запрос
логина — `git clone` падает на `could not read Username`. Поэтому доступ к GitHub
выдаётся заранее, один раз, в обычном терминале:

```bash
winget install --id GitHub.cli -e
gh auth login
```

Ответы: `GitHub.com` → `HTTPS` → `Y` (authenticate Git with GitHub credentials) →
`Login with a web browser`. Код для браузера печатается **в терминале**, никуда не
присылается. Дойти надо до строки `✓ Logged in as ...`: если закрыть окно раньше,
токен не сохранится, и авторизация в браузере окажется ни к чему не привязана.

Дальше забирает Клод. У Pathway удалённого репозитория пока нет — проект живёт
только в `E:\Projects\Pathway`; когда появится, команда та же:

```bash
gh repo clone <владелец>/<репозиторий>
npm install
```

`npm install` сам прогонит `patch-package` через `postinstall` (Swift-патч в нём —
для macOS, на Windows просто лежит без дела).

npm 11 по умолчанию блокирует `postinstall` у зависимостей и пишет про
`allow-scripts`. На запуск приложения это не влияет — Metro и Expo от них не
зависят. Если споткнётся `drizzle-kit` при генерации миграций, разрешить точечно:
`npm approve-scripts esbuild`.

## 3. Создать телефон для превью

Android Studio → **Device Manager** → **Create Device** → выбрать модель (например,
**Pixel 7**) → скачать образ системы → запустить. Это и есть «симулятор с выбором
модели»; можно завести несколько разных.

То же самое из командной строки делает Клод:

```bash
avdmanager create avd -n Pixel_7_API_37 -k "system-images;android-37.0;google_apis;x86_64" -d pixel_7
```

Берём `google_apis`, а не `google_apis_playstore`: для разработки удобнее, `adb`
работает без ограничений Play Store.

Две поправки сразу после создания, иначе превью будет дёргаться. В
`%USERPROFILE%\.android\avd\<имя>.avd\config.ini`:

- `hw.gpu.enabled=yes` — по умолчанию `avdmanager` ставит `no`, то есть
  программный рендеринг, и анимации reanimated идут рывками;
- `hw.ramSize=4096` — по умолчанию 2 ГБ, для React Native мало.

Ошибка `Could not load devices from ...\devices.xml` при создании — безвредна,
профиль устройства всё равно применяется. Проверить можно по `config.ini`:
`hw.device.name=pixel_7`, разрешение 1080×2400, плотность 420.

## 4. Запустить с живым превью

```bash
npx expo run:android
```

Первая сборка идёт ~15 минут (Gradle с нуля). Дальше приложение ставится на эмулятор,
поднимается Metro — и **любая правка кода видна в эмуляторе за секунду**. Metro
останавливать не нужно, он и есть живое превью.


### Если приложение не видит Metro

Первый запуск часто падает на `java.net.ConnectException` с LAN-адресом хоста
(`192.168.x.x:8081`) — из эмулятора этот адрес недоступен. Пробросить порт и
перезапустить приложение на `localhost`:

```bash
adb reverse tcp:8081 tcp:8081
```

**Проброс живёт до перезапуска эмулятора или adb-демона** — после каждого нового
старта эмулятора команду повторить.

## 5. Первое сообщение Клоду на новом компьютере

> Продолжаем приложение Pathway. Прочитай `CLAUDE.md` и `docs/`. Я на Windows,
> iOS недоступен — настрой меня на разработку и превью под Android через эмулятор.

Дальше Клод подхватит весь контекст из репозитория — правила, архитектуру, план — и
продолжит с того же места.

## Сборка APK для телефона (как на Mac)

Тот же путь, что в [`06-тестирование.md`](06-тестирование.md), но команды под Windows:

```bash
npx expo prebuild --platform android
cd android
gradlew assembleRelease
```

Готовый файл — `android/app/build/outputs/apk/release/app-release.apk`. Подписан
debug-ключом: ставится на телефон вручную, в Google Play не годится (для магазина
нужен свой ключ подписи).
