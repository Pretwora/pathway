## Анкеты

- **Возрастной рейтинг:** во всех вопросах «нет» → App Store 4+, Google Play — для всех.
- **App Store — App Privacy:** «Data Not Collected», ни одного типа данных.
- **Google Play — Data Safety:** «No data collected», «No data shared».
- **Шифрование (App Store):** приложение не ходит в сеть и не использует шифрование сверх встроенного в iOS → «None of the algorithms mentioned above». Чтобы вопрос не задавали на каждую сборку, можно прописать в `app.json` `ios.config.usesNonExemptEncryption: false`.
- **Права на контент (App Store):** сторонний контент — только шрифты Unbounded и Manrope (лицензия OFL) и библиотеки с открытыми лицензиями.
- **Статус трейдера в ЕС (закон DSA):** App Store Connect попросит указать до публикации в странах ЕС. Трейдеру Apple показывает в ЕС адрес и телефон; если это не нужно — не публиковать в ЕС.

Экспорт копии и «Поделиться» сбором данных не считаются: это действия пользователя, данные не уходят разработчику.

## iOS: сборка на Mac и отправка в App Store

### Один раз: подготовить Mac

1. Свежая macOS и **Xcode** из Mac App Store. После установки открыть Xcode один раз, согласиться с лицензией, дать доставить компоненты.
2. **Homebrew** (brew.sh), через него — `brew install node@24 cocoapods`. Нужен Node.js 24 LTS.
3. В `~/.zshrc` — `export LANG=en_US.UTF-8`, иначе CocoaPods падает на Unicode (`docs/06-тестирование.md`).
4. Xcode → Settings → Accounts → «+» → войти Apple ID аккаунта разработчика.

### Один раз: запись приложения в App Store Connect

appstoreconnect.apple.com → Apps → «+» → New App:

- платформа iOS, имя `Pathway - tracker`, основной язык — русский;
- Bundle ID — `com.sgrigoriev.pathway`. Если его нет в списке — зарегистрировать на developer.apple.com → Certificates, IDs & Profiles → Identifiers → «+» (или сначала сделать Archive в Xcode с автоматической подписью — он зарегистрирует ID сам);
- SKU — любой внутренний код, например `pathway`.

Имя в App Store уникально на весь магазин. Если `Pathway - tracker` занято — App Store Connect скажет при создании записи.

### Каждая сборка

```bash
git clone https://github.com/Pretwora/pathway.git   # первый раз; дальше — git pull
cd pathway
npm install                       # postinstall накладывает патч из patches/
npx expo prebuild -p ios --clean  # генерирует ios/ (в git не хранится) и ставит pods
open ios/Pathway.xcworkspace
```

В Xcode:

1. Слева проект → таргет **Pathway** → **Signing & Capabilities**: включить «Automatically manage signing», Team — свой аккаунт разработчика. Bundle Identifier подтянется из `app.json`.
2. Вверху выбрать устройство **Any iOS Device (arm64)**.
3. **Product → Archive.** Несколько минут; в конце откроется Organizer.
4. **Distribute App → App Store Connect → Distribute.** Сертификат и профиль Xcode создаст сам.
5. Ждать письма о том, что сборка обработана (обычно 10–30 минут). Она появится в App Store Connect → TestFlight.

**Номер сборки.** Apple не принимает две сборки с одинаковым номером. Перед каждой новой загрузкой увеличить `ios.buildNumber` в `app.json` (`"1"` → `"2"` …) и повторить `prebuild`. Для новой версии — ещё и `version` (`1.0.0` → `1.0.1`).

### TestFlight — проверка на своём iPhone

1. App Store Connect → приложение → TestFlight → сборка → ответить на вопрос о шифровании, если спросят.
2. Internal Testing → создать группу, добавить себя.
3. На iPhone — приложение **TestFlight** из App Store → установить Pathway.
4. Пройти чек-лист из `docs/05-подводные-камни.md`, пункт 2.

Внешние тестеры (до 10 000, по ссылке) — после короткой бета-проверки Apple первой сборки.

### Страница и отправка на ревью

1. **App Information:** подзаголовок, категория, права на контент, возрастной рейтинг.
2. **Pricing and Availability:** бесплатно, страны.
3. **App Privacy:** Get Started → данные не собираются → Publish.
4. **iOS App 1.0:** скриншоты 6.9″, рекламный текст, описание, ключевые слова, ссылки, copyright; в блоке Build — «+» и выбрать сборку; App Review Information — контакт и заметка выше; выпуск — вручную или сразу после одобрения.
5. **Add for Review → Submit to App Review.**

Статусы: Waiting for Review → In Review → Pending Developer Release (если выпуск вручную) или Ready for Distribution. Обычно от нескольких часов до двух суток. После выпуска приложение появляется в поиске в течение суток.

**Если отказ** — сообщение в App Store Connect с номером правила. Код — новой сборкой с новым номером, тексты и скриншоты — без сборки. Ответить в Resolution Center и отправить снова.

## Android: Google Play

1. **Сборка AAB** — Play принимает только Android App Bundle, не APK:
   ```bash
   android/gradlew -p android bundleRelease
   ```
   Готовый файл: `android/app/build/outputs/bundle/release/app-release.aab`. Подписать ключом загрузки (`%USERPROFILE%\.android-keys\pathway-upload.jks`, alias `pathway`) через `jarsigner` — `apksigner` для AAB не подходит. Пароль — из переменной окружения `PATHWAY_KEYSTORE_PASSWORD`.
2. **Play Console** → создать приложение `Pathway - tracker`, язык русский, бесплатно.
3. **Play App Signing** — включить: Google хранит ключ подписи, мы загружаем AAB своим ключом загрузки.
4. **Закрытое тестирование:** 12 тестировщиков, 14 дней подряд (для нового личного аккаунта, `docs/05`, пункт 3).
5. Заполнить страницу (тексты выше, картинки из `store/google-play/`), Data Safety, возрастной рейтинг, целевую аудиторию.
6. После закрытого теста — запросить доступ к рабочей версии и выпустить.
