# Pathway — как тестируем

Основной процесс на всё время разработки. Три уровня, каждый ловит своё.

| Уровень | Где | Что ловит | Сколько ждать |
|---|---|---|---|
| **1. Домен** | Компьютер, без телефона | Логика: суммы, дни, деление на ноль, границы | 1 секунда |
| **2. iOS-симулятор** | Mac, Xcode | Вёрстка, шрифты, цвета, навигация, база | 5 секунд |
| **3. Android по APK** | Живой телефон | Настоящий пользовательский сценарий, вибрация, палец | 20–40 минут |

Правило: **баг ловим на самом дешёвом уровне, где он ловится.** Логику не проверяем тыканьем в телефон, а вёрстку не проверяем тестами.

---

## Уровень 1 — домен

Чистые функции без React и SQL. Тесты идут за секунду и не требуют ничего.

```bash
npm test                  # всё
npx jest src/domain       # только домен
npx jest --watch          # перезапуск при сохранении
```

Здесь живут: суммы записей, остаток, доля пути, перевыполнение, границы и номер дня, разбор резервной копии. Всё, что можно посчитать без экрана, проверяется тут — и только тут.

---

## Уровень 2 — iOS-симулятор

Быстрый цикл на каждый день. Сборка нужна **один раз**, дальше правки прилетают сами.

**Первая сборка** (или после установки нового нативного модуля):

```bash
npm run ios
```

**Каждый день:**

```bash
npx expo start
```

Приложение уже стоит в симуляторе — просто открой его. Сохранил файл → экран обновился.

**Скриншот из терминала:**

```bash
xcrun simctl io booted screenshot ~/Desktop/shot.png
```

**Полезное:** `r` в терминале Metro — перезагрузить, `j` — открыть отладчик, `Cmd+D` в симуляторе — меню разработчика.

Чего симулятор **не** проверяет: вибрацию, реальную скорость, поведение пальца, яркость на солнце. Всё это — уровень 3.

---

## Уровень 3 — Android по APK

Главная проверка. APK ставится как обычное приложение — ровно то, что получит живой человек.

**Собираем локально**, облачных сервисов сборки не используем. Тулчейн стоит на машине (JDK 17 + Android SDK), сборка идёт у нас.

```bash
android/gradlew -p android assembleRelease
```

Готовый APK: `android/app/build/outputs/apk/release/app-release.apk`. Скидываешь на телефон, ставишь, разрешаешь установку из неизвестного источника.

Это **standalone-релиз**: JS вшит в APK, Metro не нужен — приложение работает где угодно, хоть на тренировке без связи. Gradle подписывает его debug-ключом — для установки руками достаточно; релиз переподписываем своим ключом (`docs/08-windows.md`). Каждая правка кода требует пересборки (~несколько минут после первой).

**Окружение** (разово, уже в `~/.zshrc`):

```bash
export JAVA_HOME="/opt/homebrew/opt/openjdk@17"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$PATH"
```

## Приёмка изменений

Изменение готово, когда пройдены все три:

1. `npm test` — зелёный.
2. `npx tsc --noEmit` и `npx expo lint` — молчат.
3. Сценарий отработан **руками на живом телефоне**.

Для счётчика третий пункт звучит буквально так: **сделать настоящую тренировку и посчитать подходы этим приложением.** Не «потыкать на диване» — именно на тренировке, одной рукой, между подходами. Это и есть настоящая приёмка.

## Известные грабли окружения

**CocoaPods требует UTF-8.** Если `LANG` не задана, `pod install` падает с `Encoding::CompatibilityError` на нормализации Unicode. Добавь в `~/.zshrc`:

```bash
export LANG=en_US.UTF-8
```

**Expo Go не подходит.** Публичный Expo Go умеет только SDK 54, а проект на 57 — версия для 57 застряла в ревью Apple с мая 2026. Плюс шеринг картинки в Expo Go не работает в принципе. Поэтому только development build.

**Патч Swift.** `expo-modules-jsi@57.0.3` не компилируется Xcode 26.3 — Swift 6.2 не может разрешить `abs(Double) <= Double` в контексте этого модуля. Исправление лежит в `patches/`, применяется автоматически через `postinstall`. **Если после `npm install` iOS перестал собираться — проверь, что патч применился:** `npx patch-package`.

**`rsync` из Homebrew ломает отправку в App Store.** Distribute App (или `xcodebuild -exportArchive`) падает с `Copy failed`, в логах дистрибуции — `--extended-attributes: unknown option`. Xcode зовёт системный `/usr/bin/rsync`, а тот запускает второй конец через `rsync` из `PATH` — и находит `/usr/local/bin/rsync` 3.x, который флагов системного не понимает. Экспортировать с системным `PATH`:

```bash
PATH=/usr/bin:/bin:/usr/sbin:/sbin xcodebuild -exportArchive \
  -archivePath Pathway.xcarchive -exportOptionsPlist ExportOptions.plist \
  -exportPath export -allowProvisioningUpdates
```

Из Xcode — то же самое: закрыть его и запустить из терминала без Homebrew в `PATH`, либо `brew uninstall rsync`.

**Веб отключён.** `expo-sqlite` на вебе требует `SharedArrayBuffer` и падает. Приложение мобильное, веб нам не нужен — `platforms: ["ios", "android"]`.
